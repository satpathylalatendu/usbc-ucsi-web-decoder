# Security Policy

## Supported Scope

Security reports are welcome for issues that affect:

- the Flask web application
- request handling and API behavior
- local command execution paths
- dependency-related exposure in runtime code
- accidental disclosure of sensitive local data through logs or exports

## Reporting Guidance

Please avoid posting full exploit details in a public issue.

If private reporting is available on the hosting platform, use that first. If not, open a minimal issue that states a security concern exists without publishing proof-of-concept details, stack traces containing secrets, or sensitive environment information.

## What To Include

- affected file or endpoint
- reproduction steps
- expected behavior
- actual behavior
- security impact
- any suggested mitigation

## Response Expectations

Reports should be triaged before public discussion of exploit details. Fixes may include code changes, dependency updates, documentation updates, or temporary mitigation guidance.
